# SNS投稿ライブラリ

Obsidian VaultのSNS投稿候補を美しく整理し、いつでも閲覧・検索できるモバイル最適化Webサイトです。2026-11-22のマーケティングダッシュボード化とUIリデザインv2で、左サイドバーから画面を切り替えるプロダクト型のUIになりました。投稿候補は個人アカウント用とKinapse用に分かれ、投稿したものの実績（インプレッション・返信・フォロワー増減）は「実績・分析」で追います。2026-11-22には過去のThreads実績（上位10件＋アカウントのベースライン）も実測データとして追加しました。

## デモ

Threads風のクリーンなデザインで、実際の投稿イメージを確認しながらコンテンツを管理できます。

## 特徴

- **左サイドバー**: ダッシュボード／投稿候補／個人アカウント／Kinapse用／実績・分析／アーカイブを切り替える。1画面に全部並べない（モバイルでは上部の横スクロールメニューになる）
- **アカウント別の投稿候補**: 個人アカウント（@aus_physio_masa.therapist）とKinapse用（臨床系・アカウント作成前）を分けて管理する
- **実績・分析**: 投稿済みのインプレッション、Views、いいね、返信、ターゲット返信、ターゲットフォロー、フォロワー（前→後／増減）を記録する。未記録は「未記録」と表示し、数字は作らない
- **マーケティングダッシュボード**: 下書き／承認待ち／投稿済み／要判定（48h経過）／アーカイブの件数、次に出すテスト枠3件、柱別の内訳を表示
- **Threads風デザイン**: 実際のSNS投稿と同じ見た目でプレビュー（ハンドルは `@aus_physio_masa.therapist`）
- **モバイルファースト**: スマホでの閲覧に完全最適化
- **全文表示**: メインフィードで投稿の全文を確認可能
- **高速検索**: キーワードで即座に投稿を検索
- **柱・ステータス・フック型フィルター**: 柱（海外キャリア／AIと働く日常／Kinapseを作る／臨床・Kinapse用）、ステータス、フックの型で絞り込み
- **ワンタップコピー**: 投稿文を簡単にコピー（表示時にハッシュタグと「文字数」の行を除く。`data.js` の原文は残す）
- **219件の投稿**: ライブラリ209件（既存200件＋2026-11-22のThreads短文候補6件＋Kinapse用（解剖リール01）3件）に、過去のThreads実績10件を別枠で追加。個人アカウント用116件（ライブラリ106件＋過去実績10件）、Kinapse用3件、アーカイブ100件

## 投稿データのフィールド

各投稿は `id / title / persona / content`（`data.js`）に加え、`marketing.js` で以下を持ちます（読み込み時に `app.js` が統合します）。

| フィールド | 意味 |
|---|---|
| `status` | `draft`（下書き）／`approved`（承認待ち）／`posted`（投稿済み）／`archived`（アーカイブ） |
| `pillar` | `overseas`（海外キャリア）／`ai-daily`（AIと働く日常）／`building-kinapse`（Kinapseを作る）／`clinical-kinapse-only`（臨床・Kinapse用） |
| `hookType` | フックの型（例：`ツッコミ`／`知識引き出し`／`AI機能を聞く`）。既存200件は未設定（`null`） |
| `account` | `personal`（個人アカウント）。将来 Kinapse アカウント用は `kinapse` |
| `source` | 参照元（Obsidianノート名／元リール名など） |
| `postedAt` / `postUrl` | 投稿日／投稿URL（未投稿は `null`） |
| `result48h` | 48時間後の結果 `{ impressions, views, likes, replies, reposts, targetReplies, targetFollows, followersBefore, followersAfter, followerDelta, verdict }`。未記録の項目は `null`（数字は作らない）。過去実績10件は48時間後の値ではなく2026-11-22取得時の累計で、`views` / `targetReplies` / `targetFollows` / `verdict` は未記録（`null`） |
| `nextAction` | 次にやること（1行） |
| `intent` | 狙い（1行） |

既存200件の割り当て：AIリテラシー50件→`ai-daily`・下書き、海外生活・日本比較50件→`overseas`・下書き、ビジネス戦略50件と学習と習慣50件→`building-kinapse`・**アーカイブ**（削除はしていない。「アーカイブ」画面で表示できる）。2026-11-22のThreads短文候補6件はカテゴリー「Threads短文候補」として追加し、既存200件は上書きしていない。Kinapse用3件はDrive「Kinapse 解剖リール01 Threads下書き｜2026-11-15.md」の案1・案2・案3を原文のまま収録したもの（案2はCashman ら 2026、系統的レビュー22本）。上腕二頭筋のリール02の下書きはそのファイルには無かったため、入れていない。案4・案5も同ファイルにあるが、未収録。

## 投稿予測について

カードとモーダルに出るスコアは、フック・文字数などから計算する**ヒューリスティック予測**です。実測の反応ではありません。モーダルでは「投稿予測（実測ではない）」と明記しています。実測がある投稿では、モーダルの「48時間の結果」を優先して見てください。

## 判定ルール（テストマーケティング）

- 判定は投稿から48時間後
- ヒットの目安：ターゲット（日本のPT・PT学生）からの返信5件以上、またはターゲットフォロー3人以上
- 投稿にリンク・ハッシュタグ・絵文字は入れない（方針）。表示時にハッシュタグを除くのはこのため

## 使い方

### サイトを開く

1. `index.html`をブラウザで開く
2. または`start.html`からアクセス

### 投稿を探す

1. **検索**: 上部の検索バーにキーワードを入力
2. **フィルター**: 柱のチップ、ステータス、フックの型で絞り込み
3. **閲覧**: 投稿カードで全文を確認。ダッシュボードで「次のテスト枠」を確認

### 投稿をコピー

1. 投稿カードをタップしてモーダルを開く
2. 「狙い」「参照元」「48時間の結果」「次にやること」を確認
3. 「投稿プレビュー」で実際の見た目を確認
4. 「投稿文をコピー」ボタンをタップ
5. SNSアプリに貼り付けて使用

## キャッシュと読み込みについて（2026-11-22の障害と対策）

- 2026-11-22、PR #2 マージ後のライブ確認で、初回は古いUI（206件・サイドバーなし）が表示され、再読み込み後は「読み込み中...」のまま固まる障害が起きた。
- 原因：サービスワーカー `sw.js` のキャッシュ名が `sns-posts-v7` のまま変わらず、fetch が cache-first だったため、古い `index.html` / `app.js` / `data.js` が無期限に返された。新しい `index.html` と古い `app.js` の組み合わせでは、旧 `app.js` が存在しない要素（`#postsContainer`、`#searchInput`）を触って例外を吐き、`init()` が `hideLoading()` に到達しなかった。`marketing.js` はキャッシュ対象外でもあった。
- 対策（`sw.js` は `sns-posts-v8` に更新）：アプリ本体（HTML/JS/CSS）は network-first（ネットワーク失敗時のみキャッシュにフォールバック）、`marketing.js` をキャッシュ対象に追加、スクリプト類に `?v=8` を付けた。`app.js` の `init()` は try/catch/finally で必ずローディングを消し、1件の壊れた投稿データでは全体を止めない。`app.js` が起動しなくても、6秒後にインラインの監視スクリプトがオーバーレイを消してエラーを表示する。
- それでも古い画面が出る場合：ハードリフレッシュ（Windows: Ctrl + Shift + R / Mac: Cmd + Shift + R）。それでも直らない場合はブラウザ設定からこのサイトのサービスワーカーを解除してから開き直す。
